# 决策与待确认事项

## 已确认

- 目标是评估规则与靶架位置的平衡，并研究不同新老手阵容的补偿。
- 每回合采用 120 秒作为当前实验时限。
- 用户确认场地为 23×12 米，不使用旧的 24×15 米。
- 用户确认靶架正面为 0.75×0.75 米，五孔孔径与安装高度尚未测量。
- 五个靶点位于同一块靶架，内部位置固定。
- 熟练度 eta 属于单个玩家，每局双方老手人数和程度可以不同。
- 从 Colab 开发与运行，GitHub 管理代码和配置，Drive 管理大型产物。
- 用户已要求按草图假设坐标并试跑攻防胜负，当前进入首轮脚本仿真阶段。

## 暂定实验基线，尚非最终规则

- 4v4 起步；后续比较 5v5、6v6 与人数不对称。
- 攻方无限复活，守方每人两条命；复活有等待且不自动补箭。
- 攻方开局持弓无箭，中场配给总数等于攻方人数，开局每人最多领一支。
- 守方每人配给五支，手持上限暂定三支，其余放补给点。
- 攻守掩体数量暂定 3 与 1，具体位置及尺寸未定。
- 第一套模式仅以清完五个靶点获胜，不加入全歼胜利。
- 不将原始模式的接箭/打靶复活机制自动带入新的生命规则。
- 靶架高度与朝向先固定，优先比较平面位置。

## 实现前必须处理

1. 移动/射击/拾箭边界，中线箭矢是否属于可拾取边界；首轮坐标只是草图假设。
2. 出生区、复活延迟、复活保护及防守者两条命的回场方式。
3. 靶架尺寸、五孔偏移和半径、朝向、高度；击落后是否形成贯穿孔。
4. 掩体尺寸、位置与高度，是否允许人为挡靶。
5. 移动速度、箭速、射高、射击散布、瞄准/搭箭/拾箭耗时。
6. 接箭是否保留，成功判定与满箭时的行为。
7. 守方全部离场后，攻方是否仍必须清靶；截止时刻事件如何结算。
8. “新人少于一半”的口径与启用的具体额外规则。
9. eta 阈值、能力映射和实测方法。示例参数不能冒充实测数据。

## 首轮原型的额外约定

完整配置见 `configs/attack_defense_23x12.json`。用户写的掩体尺寸 `1.*6*1` 有歧义，暂按长1×宽0.6×高1米；不能视为已确认。

- 一块五孔靶架，五孔直径暂定17厘米、中心高度1.1米，四角孔偏移±0.21米，均未实测。
- 攻方行动至x=15米，守方区域从x=15.5米开始；界线暂定。
- 新攻防模式持弓开局，进攻方拿到中场箭后无需退回原底线。
- 攻方无限复活、守方两条命；复活延迟3秒，保护0.8秒或越过保护线/捡箭即解除。保护中不可射击。
- 接箭默认关闭，原始接箭/打靶召回复活不混入本模式。
- 双方四人，攻方三人清靶、一人优先压制；守方射击可见敌人。没有 RL 训练。
- 靶架边框挡箭，已击落孔允许箭头完全通过；所有被阻挡箭矢落地可回收。
- 暂定最小射距3米；这只是模型参数，不作为现实活动安全距离建议。
- 守方全部离场仍需清靶；仅按清完五孔或超时判胜。
